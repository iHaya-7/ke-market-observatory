# Knowledge Engineering Workspace

This workspace prepares the Knowledge Engineering Market Observatory for an approved lightweight Ontology Pipeline to improve job classification, salary benchmarking reliability, and source traceability. The intended outcome is measurable improvement through a controlled before/after comparison with the existing application.

The current scope is organization only: documentation, an initial modeling-decision template, and empty stage folders. Modeling and implementation will follow later. No taxonomy concepts, ontology classes, competency questions, or evaluation results have been finalized here.

| Stage | Purpose for future work |
| --- | --- |
| Stage 0 — Baseline | Document the existing behavior and evidence before changes; retain baseline and comparison records in `07-evaluation/`. No baseline evaluation has been performed by this setup. |
| Stage 1 — Scope (`01-scope/`) | Define boundaries, intended uses, and competency questions for the lightweight enhancement. |
| Stage 2 — Vocabulary and metadata (`02-vocabulary-metadata/`) | Document terms and metadata requirements for consistent interpretation and traceability. |
| Stage 3 — Taxonomy (`03-taxonomy/`) | Develop and review classification concepts and their organization. |
| Stage 4 — Ontology (`04-ontology/`) | Define the minimal concepts, relationships, and constraints required by the agreed scope. |
| Stage 5 — Knowledge graph (`05-knowledge-graph/`) | Prepare future mappings and graph representations linked to source evidence. |
| Stage 6 — Validation (`06-validation/`) | Define and retain future checks of modeling consistency and evidence quality. |
| Stage 7 — Evaluation (`07-evaluation/`) | Plan and record a controlled before/after comparison of classification, salary reliability, and traceability. |

The existing collector, salary and job validation, review queue, bilingual dashboard, data, tests, and GitHub Pages automation remain the baseline. These stage folders do not participate in the application, build, or deployment. Future enhancements should remain lightweight and be assessed against that baseline with consistent evidence and comparison conditions.

Use [`DECISIONS.md`](DECISIONS.md) to record future modeling decisions as they are reviewed. Independent training references remain separate from Market Observatory implementation.

The workspace is ready to begin Stage 0 — Baseline and Stage 1 — Scope; neither stage is completed by this organization task.
